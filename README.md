# Integrating Conditional WGAN-GP and Reinforcement Learning for Automated De Novo Drug Discovery

This project implements a Conditional Wasserstein Generative Adversarial Network with Gradient Penalty (WGAN-GP) for *de novo* drug discovery. The model learns to generate novel molecular structures, represented as SELFIES (Self-referencing Embedded Strings), conditioned on desired physico-chemical properties.

## Significance

Automated generation of novel molecular structures with specific desired properties is a key challenge in modern drug discovery. Traditional methods can be resource-intensive and time-consuming. This project aims to accelerate this process by leveraging generative deep learning models. By training on existing datasets of molecules and their properties, the model can explore the vast chemical space and propose new candidates that satisfy predefined property criteria, potentially leading to faster identification of promising drug leads. The use of SELFIES ensures a higher validity rate of generated molecules compared to other string representations like SMILES.

## Core Technology

This project leverages several key technologies:

*   **PyTorch:** The primary deep learning framework used for implementing the neural network models (Generator and Discriminator). Its flexibility and dynamic computation graphs are well-suited for research and development of complex architectures like GANs.
*   **RDKit:** A comprehensive open-source cheminformatics toolkit. It's used for:
    *   Calculating molecular properties (e.g., QED, LogP, Molecular Weight, Lipinski descriptors) from SMILES strings.
    *   Converting SELFIES strings generated by the model back into SMILES and then into RDKit molecule objects for validation and property calculation.
*   **SELFIES (Self-referencing Embedded Strings):** A string-based representation for molecular graphs. Unlike SMILES, SELFIES strings are designed to have a much higher rate of producing valid molecules when subjected to random modifications (like those occurring during generative model training). This significantly improves the quality and usability of generated outputs.
*   **NumPy & Pandas:** Essential Python libraries for numerical computation and data manipulation, respectively. Pandas is used for loading and managing the input dataset, while NumPy supports various numerical operations.
*   **TensorBoard:** A visualization toolkit for inspecting and understanding PyTorch models, metrics, and training progress.
*   **Docker:** The `Dockerfile` provided suggests that Docker can be used for creating a containerized environment, ensuring reproducibility and simplifying dependency management across different systems.

## Model Architecture

The project employs a Conditional Wasserstein GAN with Gradient Penalty (WGAN-GP). This architecture consists of two main neural networks: a Generator and a Discriminator (Critic).

*   **Conditional Generator:**
    *   **Input:** A random noise vector and a condition vector (representing desired molecular properties).
    *   **Process:** The generator uses an LSTM (Long Short-Term Memory) network to sequentially produce a SELFIES string. The initial hidden state of the LSTM is derived from the concatenation of the noise and property vectors.
    *   **Output:** A sequence of probabilities over the vocabulary of SELFIES tokens. The Gumbel-Softmax trick is used to enable differentiable sampling from this discrete distribution during training, allowing gradients to flow back through the sampling process.
    *   **Goal:** To generate realistic SELFIES strings that correspond to the input property vector.

*   **Conditional Discriminator (Critic):**
    *   **Input:** A SELFIES string (either a real one from the dataset or a fake one from the generator) and its corresponding property vector.
    *   **Process:** The discriminator also uses an LSTM to process the input SELFIES string. The final hidden state of the LSTM, concatenated with the property vector, is fed into a linear layer to produce a scalar score.
    *   **Output:** A scalar value representing how "real" the input SELFIES string appears given the conditioning properties.
    *   **Goal:** To distinguish between real molecules (from the training data) and fake molecules (generated by the Generator), given the specific properties.

The WGAN-GP framework is used to stabilize GAN training. It modifies the standard GAN loss function and introduces a gradient penalty term that enforces the 1-Lipschitz constraint on the discriminator, preventing issues like mode collapse and vanishing gradients.

## Dataset

The model is trained on a dataset of molecules, where each molecule is represented by its SELFIES string and a set of associated chemical properties.

*   **Format:** The training script (`train.py`) expects the data to be in a CSV file. The default path is `zinc_selfies_with_props.csv`.
*   **Required Columns:**
    *   `SELFIES`: The SELFIES string representation of the molecule.
    *   Property columns used for conditioning.
*   **Conditional Properties:** The model is conditioned on the following molecular properties, which should be present as columns in the input CSV:
    *   `QED`: Quantitative Estimate of Drug-likeness.
    *   `LogP`: The octanol-water partition coefficient, a measure of lipophilicity.
    *   `Molecular_Weight`: The molecular weight of the compound.
    *   `Lipinski_H_Bond_Donors`: Number of hydrogen bond donors (according to Lipinski's rules).
    *   `Lipinski_H_Bond_Acceptors`: Number of hydrogen bond acceptors (according to Lipinski's rules).
    *   `Lipinski_Rule_Violation`: A flag or count indicating violations of Lipinski's Rule of Five.

The `SelfiesConditionalDataset` class in `train.py` handles loading this data, tokenizing the SELFIES strings, and preparing the property vectors for the model.

## Running the Training

The `train.py` script is used to train the conditional WGAN-GP model.

**Basic Command:**

```bash
python train.py [OPTIONS]
```

**Key Command-Line Arguments:**

You can customize the training process using various command-line arguments. Here are some of the important ones:

*   `--data_path`: Path to the input CSV dataset (default: `~/project/DeNovo_DrugDiscovery/zinc_selfies_with_props.csv`).
*   `--output_dir`: Directory to save checkpoints and TensorBoard logs (default: `~/projects/DeNovo_DrugDiscovery/outputs/exp1`).
*   `--batch_size`: Batch size for training (default: 1024).
*   `--noise_dim`: Dimension of the input noise vector for the generator (default: 128).
*   `--prop_dim`: Dimension of the property vector for conditioning (default: 6, corresponding to the properties listed in the Dataset section).
*   `--hidden_dim`: Hidden dimension size for LSTMs in Generator and Discriminator (default: 1024).
*   `--embed_dim`: Embedding dimension for SELFIES tokens (default: 512).
*   `--max_len`: Maximum length of SELFIES sequences (default: 100).
*   `--lr`: Learning rate for Adam optimizers (default: 2e-4).
*   `--n_critic`: Number of discriminator updates per generator update (default: 5).
*   `--lambda_gp`: Gradient penalty coefficient for WGAN-GP loss (default: 15.0).
*   `--num_epochs`: Total number of training epochs (default: 200).
*   `--checkpoint_interval`: Save model checkpoint every N epochs (default: 5).
*   `--seed`: Random seed for reproducibility (default: 42).
*   `--tau_start`, `--tau_end`, `--tau_anneal_epochs`: Parameters for Gumbel-Softmax temperature annealing.

**Example Usage:**

```bash
python train.py     --data_path /path/to/your/zinc_selfies_with_props.csv     --output_dir /path/to/your/output_directory     --batch_size 512     --num_epochs 100
```

**Distributed Training:**

The script is set up for distributed training using `torch.distributed` (specifically with the `nccl` backend, suitable for NVIDIA GPUs). To run in a distributed manner, you would typically use a launcher like `torchrun` or `mpirun`.

Example using `torchrun` (assuming 2 GPUs):

```bash
torchrun --nproc_per_node=2 train.py [OTHER_ARGUMENTS]
```

The script uses environment variables like `LOCAL_RANK` to manage device placement in a distributed setup. Ensure your environment is configured correctly for distributed PyTorch training if you intend to use this feature.

## Reproducibility

Ensuring reproducibility is important in scientific research. This project takes the following steps to aid reproducibility:

*   **Random Seeds:** The `train.py` script sets random seeds for PyTorch, NumPy, and Python's `random` module using the `--seed` command-line argument (defaulting to 42). This helps in obtaining consistent results across runs, provided the same environment and data are used.
*   **Deterministic cuDNN:** The script attempts to force cuDNN to use deterministic algorithms by setting `torch.backends.cudnn.deterministic = True` and `torch.backends.cudnn.benchmark = False`. However, complete determinism on GPUs can sometimes be challenging.
*   **Environment:**
    *   The `requirements.txt` file specifies the versions of the core Python dependencies. Creating an environment from this file should lead to a similar setup.
    *   The provided `Dockerfile` offers a more robust way to create a consistent runtime environment across different machines.
*   **Hyperparameters:** All key hyperparameters are exposed as command-line arguments in `train.py`, allowing for precise control and documentation of the experimental setup.

While these measures are in place, achieving perfect bit-for-bit reproducibility in deep learning, especially with distributed training on GPUs, can be difficult due to factors like non-deterministic GPU operations and differences in hardware or software library versions at a very low level.

## How it Works / Methodology

This project combines a Conditional Wasserstein GAN with Gradient Penalty (WGAN-GP) with a reinforcement learning (RL) component to generate novel SELFIES strings representing molecules with desired chemical properties.

**1. SELFIES Representation:**
Molecules are represented using SELFIES (Self-referencing Embedded Strings). SELFIES are designed to be more robust than SMILES for generative tasks, as random modifications to SELFIES strings have a much higher probability of resulting in valid molecular structures. This reduces the burden on the generator to learn complex SMILES grammar and improves the quality of generated outputs. The input SELFIES are tokenized, and a vocabulary is built from these tokens.

**2. Conditional WGAN-GP Core:**
*   **Generator (G):** Takes a random noise vector and a target property vector (e.g., desired QED, LogP) as input. It uses an LSTM to generate a sequence of SELFIES tokens. Gumbel-Softmax sampling is employed during training to allow differentiable sampling from the categorical distribution of tokens at each step.
*   **Discriminator/Critic (D):** Takes a SELFIES string (either real or generated) and its associated property vector as input. It also uses an LSTM to process the SELFIES string and outputs a scalar score indicating how "real" the molecule looks given the properties.
*   **Wasserstein Loss with Gradient Penalty:** The training objective is based on the Wasserstein distance, which provides a more stable loss signal than the original GAN formulation. A gradient penalty is applied to the discriminator's gradients with respect to its input, enforcing the 1-Lipschitz constraint required by the Wasserstein GAN theory. This helps prevent mode collapse and ensures more stable training.

**3. Property Conditioning:**
Both the generator and discriminator are *conditional*. This means they don't just learn to generate/evaluate molecules in general, but do so *based on specific input properties*.
*   The generator receives the desired property vector alongside the noise input, guiding it to produce molecules that should exhibit these properties.
*   The discriminator receives the property vector alongside the molecule, allowing it to assess if the molecule is realistic *for a compound with those properties*.

**4. Reinforcement Learning (RL) for Property Optimization:**
While the GAN framework learns to generate realistic molecules conditioned on properties, an additional RL component is used to explicitly reward the generator for producing molecules that match desired property profiles accurately.
*   **Reward Calculation:** After the generator produces a batch of SELFIES strings (from Gumbel-Softmax probabilities, then taking `argmax` to get discrete tokens), these are decoded into SMILES and then to RDKit molecule objects.
*   **Property Evaluation:** Properties like QED are calculated for these generated molecules.
*   **Reward Signal:** A reward is computed based on how well the generated molecules' properties match the target properties or achieve certain desirable scores (e.g., high QED). In this implementation, the QED score itself is used as a reward.
*   **Policy Gradient:** This reward signal is used to adjust the generator's weights. The generator's loss function includes a term that encourages it to maximize this expected reward. This helps fine-tune the generator to produce molecules that are not only realistic but also optimized for the target properties. The `compute_property_reward` function in `train.py` implements this.

**5. Training Process:**
*   The discriminator is trained to distinguish between real (dataset) and fake (generated) molecule-property pairs.
*   The generator is trained to fool the discriminator *and* to maximize the property-based reward.
*   The discriminator and generator are trained iteratively (typically with more discriminator updates per generator update, controlled by `n_critic`).
*   Gumbel-Softmax temperature (`tau`) is annealed over epochs, starting higher (more exploration) and decreasing (more exploitation).

## Future Work

There are several avenues for extending and improving this project:

*   **Expanded Property Sets:** Incorporate a wider range of molecular properties for conditioning, including ADMET (Absorption, Distribution, Metabolism, Excretion, Toxicity) properties or target-specific binding affinities if such data is available.
*   **Advanced Molecular Representations:** Explore other molecular representations beyond SELFIES, such as graph-based representations directly processed by Graph Neural Networks (GNNs).
*   **More Sophisticated Reward Functions:** Develop more complex reward functions for the RL component, potentially combining multiple desired properties or incorporating penalties for undesirable substructures.
*   **Hyperparameter Optimization:** Conduct systematic hyperparameter optimization (e.g., using Bayesian optimization or grid search) to find the best performing model configurations.
*   **Scalability and Efficiency:** Further optimize the code for training on larger datasets and explore more advanced distributed training strategies.
*   **Web Application/API:** Develop a user-friendly interface or an API to allow users to input desired properties and receive generated molecular candidates.
*   **Experimental Validation:** The ultimate test for any drug discovery model is experimental validation. Generated candidates would ideally be synthesized and tested in vitro/in vivo.
